# 2.0.2 代码质量检查与修复

范围：原生主题读写、事件缓存、COM 菜单、身份校验、部署助手、一级菜单初始化、安装器与构建脚本、三组原生测试。基于已发布 2.0.2，修改保存在独立开发分支；不更改公开发行物或本机已安装程序。

采用 ECC cpp-coding-standards 与 verification-loop。目标是修复有证据的问题，保持现有产品行为，不为小项目引入新的框架或抽象层。

## 检查清单和结果

| 方面 | 结果与处理 |
| --- | --- |
| 清晰度、重复与包装 | CleanupOld 和 DiscardVersion 的相同文件清理合并为 RemoveOwnedVersion；保留明确拥有所有权标记、固定文件列表和非递归删除的约束。未增加接口框架或第三方库。 |
| 异常输入 | 版本号现在限定为三个非空十进制段，拒绝点路径及分隔符；未知非空 Backend 报错，不误选卸载路径。无效模式和空写入函数指针明确拒绝。 |
| 错误传播 | 部署注册表读取只对确实缺失返回空值，其他错误向上传递；一级偏好读取区分缺失、非法类型、非法值，避免把失败当成可覆盖的默认状态。 |
| 资源与生命周期 | 缓存停止后发布不可用快照，不保留看似可操作的旧状态；重复停止和恢复仍受原有生命周期锁保护。 |
| 并发 | COM LockServer 解锁改用 compare/exchange，避免多个解锁者使计数变负；新增并发解锁回归。 |
| COM 接口契约 | 标题、图标、提示文字回调明确拒绝空输出指针，返回 E_POINTER。 |
| 文件清理 | 预检与清理拒绝 components 根目录重解析点；共享清理函数将所有权标记放在最后，文件删除失败后可重试。忽略目录非空仅用于保留额外用户文件，其他删除错误报告。 |
| 测试保护 | 增加损坏安装状态、非法偏好、注册表类型错误、无效模式、空 writer、停止快照、重复操作、COM 空指针与并发服务器锁测试。 |
| 依赖与复用 | 保持 C++20、Windows API、MSVC 静态运行库和原有构建工具；旧恢复源码不参与原生编译，无新增运行库依赖。 |
| 网络与部署失败 | 主题切换和缓存不使用网络；身份包部署异常仍以失败状态和安装器错误文件向上传递。未引入网络重试或更新服务。 |
| 安装器 | 原有备份、版本部署、失败恢复及目录清理规则保留；四种真实 Inno 隔离夹具通过。未无人值守替换真实安装或修改证书。 |
| 性能与资源 | 缓存命中仍只读原子内存，100,000 次命中不增加注册表读取；无定时轮询。没有证据支持改用更复杂缓存或常驻进程。 |

- 基线构建、测试通过：3/3，回调组 P95 0.0001 ms。

- 最终回调组 P95 0.0003 ms，P99 0.0004 ms，满足原有 1 ms 预算。此处为标题、图标、状态的一组缓存回调，不是整个菜单打开时间。与基线的极小差异没有统计对照，不声称性能提升或退化。
- Inno 目录夹具四种场景通过：旧规则对照、新目录、预先存在的空目录、额外用户文件保留。
- PowerShell 脚本解析通过，git diff --check 通过。
- 检查异常处理和清理调用；没有新增下载、shell 执行、证书操作或应用依赖。
- 未测量代码覆盖率；没有将测试组通过率解释为覆盖率。

## 保留的边界

内部一级菜单设置接口仍有 Windows 版本兼容风险；本次不重构它的 ABI。缺少接口时的退出码 20 仍允许系统默认布局，真正操作失败仍返回失败。

错误文件写入仍是尽力而为：日志路径不可写时，助手返回非零退出码，安装器仍可显示错误代码，但可能没有详细文本。没有用日志失败覆盖最初的部署失败。

本次没有完成跨 Windows 版本、多用户身份部署、真实安装失败恢复的全面端到端验收，也没有重复安装到用户正在使用的环境。测试中所用注册表为随机隔离子树，部署测试通过进程局部重定向执行，不注册实际身份包。

原有代码仍有紧凑排版；本次优先处理有行为证据的问题，没有对安装器和所有源码做无差别格式化。产品功能和版本号保持 2.0.2；本分支构建产物不是新的正式发行版。
