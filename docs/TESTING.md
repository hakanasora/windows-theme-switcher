# 2.0 验证记录与手动测试

当前为开发验证阶段。自动测试通过不代表整个 Windows 菜单弹出速度、覆盖升级或跨系统兼容已经通过。

## 自动检查

运行 `build.ps1`，CTest 执行：

- 浅色、深色、混合和无效状态；文字/图标目标一致。
- 两项设置写入；部分写入失败恢复原值；恢复失败明确报错。
- 使用随机命名的 `HKCU\Software\ThemeSwitcher.NativeTests` 子键验证真实注册表通知，不修改 Windows 的实际颜色设置。
- 100,000 次缓存命中不增加注册表读取计数；空闲期间没有周期刷新。
- 外部变化、无效状态恢复、反复启动和停止、通知与关闭的竞争、句柄数量检查。
- 未注册 DLL 的 COM 创建、无子菜单、分隔标志、10,000 组缓存回调性能及反复加载卸载。
- 主程序空参数、无效参数及多余参数均不切换实际主题。

1 毫秒 P95 预算仅针对已加载组件的缓存回调；首次 DLL 加载和真实菜单绘制分别测量，不混为一谈。

## 开发证书与安装前提

构建输出中的 `ThemeSwitcher.Development.cer` 只含公钥。先核对旁边 `DEVELOPMENT-CERTIFICATE.txt` 的 Subject 和指纹。不要导入未知证书或私钥文件。

在明确授权的测试环境中，手动双击该 `.cer`，选择“安装证书 → 本地计算机 → 将所有的证书都放入下列存储 → 受信任的人（Trusted People）”。本原型按全机安装部署，使用计算机级信任；不要放入“受信任的根证书颁发机构”。此操作需要管理员权限。

安装器自身不完成上述信任操作。未信任开发证书时应在写入程序文件前停止，并给出可读提示。正式发布不应要求用户执行这一步。

完成测试、卸载开发版本后，可在计算机证书管理中按同一指纹移除这张开发公钥证书。用于签名的个人存储私钥不会打包、导出或进入 Git。

## 必须手工完成的验收

| 场景 | 当前状态 | 验收内容 |
| --- | --- | --- |
| 当前 Windows 11 Beta | 待安装联调 | 桌面一级与应用扩展设置、重复打开后状态新鲜、旧菜单无重复入口 |
| Windows 11 稳定版 | 待测试 | 桌面专用注册、两类菜单、分组、图标与状态 |
| Windows 10 / 更早 Windows 11 | 待测试 | 仅传统菜单，无身份包注册，单个动态入口 |
| 标准用户账户 | 待测试 | 安装后可切换自己账户的模式，无管理员提示 |
| 原始 1.0 → 2.0 | 待测试 | 自动复用目录，应用列表只有一个条目，旧双菜单与分隔项移除 |
| 2.0 重装 / 后续版本 | 待测试 | 无重复注册，保留主菜单显示偏好，旧版本目录清理 |
| 安装失败 / 取消 | 待测试 | 旧程序、菜单、卸载入口恢复可用，没有静默的半套安装 |
| 卸载确认前取消 | 待测试 | 不提前移除菜单或身份包 |
| 完整卸载 | 待测试 | 菜单、包身份、组件和卸载项移除，当前颜色模式不改变 |
| 首次与连续右键 | 待测试 | 与未安装扩展时对比，分别记录首开及多次打开，不用回调微基准代替 |

主题变化后应在下一次菜单打开时得到新目标；已展开的菜单保持文字、图标和点击动作一致。通过系统设置改色和其他工具改色都需覆盖。

更新被占用的组件时，允许给出一次明确的关闭/刷新提示；不强制结束资源管理器。失败恢复和清理测试必须通过后，才可对正式版宣称无缝升级与完整卸载。
