# 2.0.2：卸载后空安装目录清理

用户报告：卸载后 C:\Program Files (x86)\ThemeSwitcher 仍为空目录；后续安装又提示目录已经存在。

检查时，实际目录已是重新安装的完整 2.0.1，包含安装条目和已注册身份包，因此没有删除当前安装，也没有把这些正常文件视作卸载残留。

## 原因及修改

安装准备阶段提前创建 `.upgrade-recovery`，连带创建安装根目录；原 Inno 规则未显式要求删除这一预先存在的目录。安装日志只记录 components/assets 的创建，也与该路径相符。

- 将自有目录规则提取为 InstallDirectories.iss，明确记录 uninsalwaysuninstall。
- 卸载最后尝试删除空的版本目录、components、assets 和安装根目录。
- 保留额外用户文件，不递归清空目录。
- 已有空目录不再弹出目录存在确认；原有非空无归属目录的拒绝覆盖检查仍保留。
- 取消/失败时，仅尝试删除本次新建且已经空的根目录，不删除恢复备份或未知内容。

## 实际测试

隔离 Inno 安装夹具使用低权限，先在 PrepareToInstall 预建根目录，再安装并卸载测试文件。不会注册真实菜单，不运行正式产品卸载器。

| 场景 | 结果 |
| --- | --- |
| 旧规则对照 | 复现卸载后留下空安装根目录 |
| 修复规则：新目录 | 卸载后根目录不存在 |
| 修复规则：预先存在的空目录 | 卸载后根目录不存在 |
| 修复规则：安装后添加 user-note.txt | 自有文件与空子目录移除，用户文件保留 |

实际已安装产品的整体验收仍需从普通桌面运行新版安装器。先覆盖安装 2.0.2，才能将新规则写入卸载器；仅生成新安装包不会修复旧卸载器。

传统菜单独立分组仍为已知未完成项；其余功能沿用 2.0.1。

依据：[Inno 目录跟踪](https://jrsoftware.org/ishelp/topic_dirssection.htm)、[卸载附加清理](https://jrsoftware.org/ishelp/topic_uninstalldeletesection.htm)。
